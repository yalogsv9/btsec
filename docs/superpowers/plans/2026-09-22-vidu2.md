# Vidu2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a database-backed custom username-or-email login example while retaining the Vidu1 flow.

**Architecture:** H2 stores `Role` and `AppUser`. A `CustomUserDetailsService` provides principals to the Vidu2-only security chain; an ordered Vidu1 chain preserves the existing in-memory demo.

**Tech Stack:** Java 17, Spring Boot 3.5.0, Spring Security 6, Spring Data JPA, H2, Thymeleaf, JUnit 5, MockMvc.

**Spec:** `docs/superpowers/specs/2026-09-22-vidu2-design.md`

## Global Constraints

- Keep Java 17 and Spring Boot 3.5.0.
- Do not create a README.
- Keep Vidu1 operational at `/vidu1`.
- Finish every Vidu2 change in one commit: `feat: add vidu2`, with no `Co-authored-by` trailer.

### Task 1: Add red web-security tests

**Files:** Create `src/test/java/vn/edu/ltweb/springws/vidu2/Vidu2SecurityIntegrationTest.java`.

**Interfaces:** Tests require `/vidu2`, `/vidu2/login`, `user01`, `user01@gmail.com`, and `/vidu2/admin/**`.

- [ ] Write MockMvc tests for anonymous redirect to `/vidu2/login`, successful form login by username and email, invalid login redirect to `/vidu2/login?error=true`, role-based admin denial, rendered `Nguyễn Hữu Trung`, and CSRF logout.
- [ ] Run `mvn test -Dtest=Vidu2SecurityIntegrationTest`; expect failures because Vidu2 routes do not exist.

### Task 2: Add persistence and principal types

**Files:** Modify `pom.xml`; create `vidu2/model/Role.java`, `AppUser.java`, `repository/RoleRepository.java`, `AppUserRepository.java`, `security/CustomUserDetails.java`, `CustomUserDetailsService.java`, and `Vidu2DataInitializer.java`.

**Interfaces:** `AppUserRepository.findByUsernameOrEmail(String username, String email)` returns `Optional<AppUser>`; the principal exposes username, email, fullName, images, and role.

- [ ] Add JPA and H2 dependencies plus H2 datasource/DDL settings.
- [ ] Model role and user uniqueness/relationship and seed `ROLE_USER` plus user01 with BCrypt `123456`.
- [ ] Implement the `UserDetailsService` lookup by username or email.
- [ ] Run the Vidu2 tests; expect routing/security failures only.

### Task 3: Split security chains and add UI

**Files:** Modify `vidu1/SecurityConfig.java`; create `vidu2/Vidu2SecurityConfig.java`, `Vidu2Controller.java`, and Vidu2 Thymeleaf templates/fragments.

**Interfaces:** Chain order 1 handles `/vidu1/**`; order 2 handles `/vidu2/**`. The Vidu2 login processing endpoint is `/vidu2/login`, success URL `/vidu2`, and logout URL `/vidu2/logout`.

- [ ] Narrow Vidu1 chain matcher and change its login/logout URLs to `/vidu1/login` and `/vidu1/logout` without changing its credentials.
- [ ] Add the Vidu2 DAO provider, username/email login, authenticated `/vidu2`, and `ROLE_ADMIN` protection at `/vidu2/admin/**`.
- [ ] Render a shared Vidu2 header using `CustomUserDetails` fields and a default avatar.
- [ ] Run `mvn test`; expect all Vidu1 and Vidu2 tests to pass.

### Task 4: Verify and commit

**Files:** Modify only project files from Tasks 1–3 and the Vidu2 spec/plan.

- [ ] Run `mvn test` and manually run `mvn spring-boot:run` to verify both `/vidu1` and `/vidu2`.
- [ ] Stage only `pom.xml`, `src`, and the two Vidu2 docs; commit with `git commit -m "feat: add vidu2"`.
